# 项目概览：ADK 把哪些责任放进框架

ADK 是以 Python 代码定义 Agent、工具和执行流程的开发工具包。本文分析 Python v2.10.0，不将其他语言实现的能力自动算入。它把模型调用纳入有会话、有事件、有生命周期的程序；应用仍负责业务规则、身份校验和外部系统的副作用。

## 五个对象的关系

**Agent 定义行为。** 顶层 Agent 是 LlmAgent 的别名，声明模型、指令、工具与子 Agent。它不是用户的聊天记录容器。[继承与别名](../references.md#e-adk-002)

**Runner 组织调用。** 它持有服务和根节点，查找会话、建立调用上下文并消费事件。“无状态执行引擎”指会话数据交给服务管理，不代表 Runner 没有成员。复用 Runner 时不要往 Agent 属性塞用户数据。[执行入口](../references.md#e-adk-003)

**Workflow 定义图。** 函数、Agent 和其他节点可以组合成图，边决定后续执行对象，路由决定采用哪条路径。BaseNode 使 Agent 与普通节点共享执行契约。SequentialAgent、ParallelAgent、LoopAgent 也是可用的编排对象；不要把图能力都归到 LlmAgent。[节点模型](../references.md#e-adk-004)

**Context 承载当前节点的运行信息。** 它与调用级 InvocationContext 不是同一对象，也不是存储所有用户信息的全局变量。[公开入口](../references.md#e-adk-001)

**Event 连接执行和记录。** 模型内容、工具调用及返回、状态变化、节点输出和路由沿事件通道传递。消费事件可以观察发生过什么；每条事件不一定都是用户应看到的最终回答。[数据模型](../references.md#e-adk-005)

## 核心理念与代价

从源码可归纳三个设计选择：声明行为与执行服务分开，使同一 Agent 定义用于不同会话；用事件通道连接模型、工具与节点，为调试和恢复提供共同材料；通过模型与服务接口保留部署选择。这些是架构分析，不是性能或可靠性保证。

代价是概念数量较多，恢复语义还依赖后端和运行模式。可靠应用需要分别考虑“框架记录了状态”和“外部系统完成了动作”。

## 四种数据不要混用

Session 是一次对话的数据边界，包含历史事件与状态；State 是带待提交差量的键值视图；Memory 是跨会话的存入与检索服务；Artifact 是内容对象与版本保存服务。记住一轮变量不等于长期记忆，保存文件也不等于模型自动读过它。

InMemorySessionService 按应用、用户、会话分层保存数据，适合学习测试；重启丢失，源码明确提示不用于多线程生产环境。[存储结构](../references.md#e-adk-006)
