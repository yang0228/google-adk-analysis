# 选型边界

以下是架构判断，不是框架排行榜。先确认系统中最难的部分，再看框架能承担多少。

| 你的约束 | ADK 值得验证的机制 | 应用必须验证 |
| --- | --- | --- |
| 现有 Python 业务函数 | 工具封装与 Runner 调用闭环 | 参数、权限、超时、重试 |
| LLM 与确定步骤混合 | Agent、函数节点、Workflow 路由 | 分支覆盖、循环上限、补偿 |
| 多用户连续对话 | Session 服务与分层 State | 身份映射、后端隔离、并发 |
| 审批后执行动作 | RequestInput 暂停与响应恢复 | 审批身份、重复响应、副作用防重 |
| 已有 Google Cloud | 云服务集成与部署入口 | IAM、网络、费用、数据区域 |

若只是一次独立结构化模型调用，完整 Agent 运行时的概念成本可能超过收益。若难点是跨系统事务，Agent SDK 不能自动提供业务补偿或 exactly-once。应先用代表性工作负载验证，再决定引入范围。
